# Demo Dataset — Profiles & Photos

Synthetic profile catalogue for the demo build. Everything here is fictional
except the photographs, which are Creative Commons works with recorded
attribution.

## Where it comes from

| Piece | Source |
| --- | --- |
| Photos | Openverse API, `license_type=commercial,modification&mature=false` |
| Profiles | generated by `scripts/generate-profiles.mjs` (seeded, deterministic) |

Only licenses that are **both commercial and modification-allowed** were taken:
CC0, PDM, CC-BY and CC-BY-SA. Anything NC (non-commercial) or ND (no
derivatives) was filtered out at the API level. `mature=false` keeps explicit
material out. Attribution is required for CC-BY and CC-BY-SA and is recorded
per image.

**No API key is needed** for this source, which is why it was used: Unsplash,
Pexels and Pixabay all require a key, and Unsplash reviews new apps for days.
To upgrade to proper stock photography later, get a Pexels or Pixabay key and
replace the files — nothing in the app needs to change.

## Regenerating

```bash
npm run data:build        # photos + profiles
npm run data:photos       # 600 portraits only
npm run data:profiles     # 200 profiles only
```

`fetch-portraits.mjs` downloads Openverse thumbnails, and `sharp` re-encodes
each one to a 400×400 WebP (`fit: cover`, `position: attention`) at ~13 KB.
One tile serves both the avatar slot and the profile grid, so 600 images cost
7.6 MB instead of ~30 MB of proxy JPEGs.

`generate-profiles.mjs` is seeded (`--seed`, default `20260925`), so re-runs
produce identical output and diffs stay small. It assigns every photo exactly
once, so no two profiles share a gallery.

## Output

| Path | Contents |
| --- | --- |
| `public/portraits/generated/*.webp` | 600 portraits, 400×400 |
| `public/portraits/generated/CREDITS.json` | per-image title, creator, license, license URL, provider, source page, original URL |
| `src/data/profiles.generated.json` | 200 profiles, 230 KB |

Profile fields match the existing `Profile` type: name, username, gender, city,
district, age, height, weight, languages, verified / verificationStatus, vip,
top, rating, ratingCount, likes, views, favoriteCount, status, joined, photo,
gallery, `about` in ru/he/ar/en, and `params`. Contacts are fabricated and
marked `(demo)`.

## How it is loaded

`src/lib/profiles-catalog.ts` pulls the JSON with a **dynamic import**, so the
230 KB is a separate chunk rather than main-bundle weight on every page. It
merges the generated set with the hand-written demo profiles at read time:

- `useAllProfiles()` → `Profile[]` for lists (directory, favourites)
- `useProfile(id)` → resolves across both sets

Swapping in real data later means replacing the JSON and the image files only.

## Known limitations

- The photographs are CC-licensed community content, not professional stock.
  Many are archival or amateur, so the visual quality is noticeably below what
  a Pexels/Pixabay key would give. The aesthetics lean vintage rather than
  modern studio.
- Every profile gets 3 photos, so the "posts" count is 3 everywhere. A real
  dataset should vary this.
- Avatar and grid tile are the same 400×400 crop, so there is no separate
  high-resolution hero shot per profile.
- `isDemoGenerated: true` marks every generated profile, which real data must
  drop.
- The generator assumes adults (ages 21–44). Real data needs its own age
  verification and moderation before it goes anywhere near a live catalogue.

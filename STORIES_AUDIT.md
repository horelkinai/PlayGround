# STORIES_AUDIT.md

Аудит механики stories/statuses в локальном приложении.
Дата: 2026-09-25. Приложение не изменялось — только чтение кода и прогон браузера.

- Локальный URL: `http://127.0.0.1:8080`
- Разрешения: desktop 1440×900, mobile 390×844
- Браузер: Chromium (Playwright, локальная сборка `chromium-1243`)
- Ограничения соблюдены: только localhost, без внешних сервисов, без авторизации,
  без cookies чужих аккаунтов, без сторонних медиа и API

> Примечание об инструменте: MCP-сервер Playwright зарегистрирован, но его
> инструменты подгружаются при старте сессии агента, поэтому в этой сессии
> `browser_*` недоступны. Аудит выполнен локальной библиотекой Playwright —
> это тот же движок и та же сборка Chromium.

## 2. Текущий store и модель данных

Ключ localStorage: `i11-store-v3` (`src/lib/store.ts:15`).
Persist пишет фиксированный снапшот ключей (`src/lib/store.ts:205-243`).

### Состояние, относящееся к ленте

```
likes:        Record<string, boolean>   // по postId / reelId
favorites:    Record<string, boolean>   // по profileId
follows:      Record<string, boolean>   // по profileId
savedPosts:   Record<string, boolean>   // по postId
blocked:      string[]                  // profileId
extraComments / extraReviews / extraReports
myProfile, agencyProfile, adminStatus, demoAdmin
```

### Отсутствует в store

`seenStories`, `storyViews`, `activeStory`, `storyProgress`,
`storyReactions`, `myStoryDraft` — **ни одного из этих полей нет.**

### Модель данных

`src/lib/types.ts` содержит `Post` (фото[], подпись, лайки, комментарии, дата) и
`Reel` (одно фото, подпись, лайки, комментарии). Типа `Story` / `StoryItem`
не существует. Stories сейчас — это **не сущность данных**, а проекция
`Profile[]`: аватар + имя, выведенные в горизонтальную ленту.

Данные для stories переиспользуются из профилей:
`gallery: string[]` (1-2 фото) и `REELS.some(r => r.profileId === id)`.

## 5. Проблемы UI/UX

### P0 — блокирующие

**P0-1. Аватары неквадратные, кольцо эллиптическое.**
`home.tsx:45` — контейнер `w-16` (64px), а содержимое требует
`60 (img) + 2×1 (p-[1px]) + 2×2 (border-2) = 66px`. Flex сжимает `<img>`
до **54×60**, кольцо получает **64×70** вместо 66×66. Воспроизводится
одинаково на 1440px и 390px — это дефект вёрстки, не масштаба.

**P0-2. Механики statuses нет вообще.**
Тап по аватару уводит на страницу анкеты. Пользователь не может посмотреть
историю, переключить её или закрыть. Сейчас это статичная лента ссылок.

**P0-3. Кольца не несут состояние, логика мертва.**
`home.tsx:58-65`: ветка `hasNew` достижима только для неподтверждённых
профилей. Из 7 историй 5 верифицированы и получают **одинаковый** градиент
`amber → accent → pink`. Измеренные классы:

| Анкета | Кольцо |
|---|---|
| noa, lina.r, maya.h, sofia.n, rina.a | `from-amber-400 via-accent to-pink-500` |
| daria.e | `from-yellow-400 via-pink-500 to-purple-600` |
| yael.j | `bg-line` (плоский) |

Нет `seen`/`unseen`, поэтому кольцо не может измениться после просмотра —
это и есть отсутствующая «механика», а не только UI.

### P1 — заметные

**P1-4. Desktop 1440: лента stories недоиспользована и не выровнена с лентой.**
Переполнения нет (596px контента), полосы прокрутки нет, полоса прижата
влево в широком layout, тогда как `shell.tsx` ограничивает фид `max-w-5xl` —
границы не совпадают, справа пустое поле.

**P1-5. Reels на desktop — 1184×868, горизонтальный кадр.**
Вертикальный формат 9:16 не выдержан: картинка растянута, выглядит как фото.
На mobile 390×724 корректно. Плюс фильтр `gender === "women" && (verified || vip)`
пропускает **4 из 6** reels (`r4` daria, `r6` adam отсеиваются) — контента мало.

**P1-6. «+Вы» без аватара и без бейджа добавления.**
Пустой круг с текстовым плюсом 2xl; визуально читается как заглушка.

**P1-7. Подписи 11px с `truncate` при ширине 64px.**
`lina.r`, `sofia.n` помещаются, но любое имя длиннее ~7 символов обрежется
без многоточия.

### P2 — улучшения

**P2-8.** Нет обработки `prefers-reduced-motion` для авто-переключения
(нужна, когда появится таймер).

**P2-9.** Нет превью историй на странице анкеты.

**P2-10.** В `i18n.ts` нет строк для интерфейса viewer — только `yourStory`,
`newBadge`, `reelsStrip`.

**P2-11.** Сторис не вынесены в отдельный компонент: логика колец, разметка и
сортировка живут внутри `home.tsx` — сложно тестировать и переиспользовать
(например, на странице анкеты).

## 10. Вывод

Полоса stories существует и работает как витрина, но **механики statuses
в приложении нет**: нет модели данных, нет viewer, нет состояния
«просмотрено», нет таймера. Кольца — статический декор, причём с дефектом
геометрии (аватар 54×60 вместо 60×60).

Рантайм чистый: 0 ошибок консоли, 0 упавших запросов, 685 запросов без
единого ответа ≥400. Работать над улучшением есть что — начинать следует
с P0-1 (геометрия) и P0-2/P0-3 (viewer и состояние колец).
